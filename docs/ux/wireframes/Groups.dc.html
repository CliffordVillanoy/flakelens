Design note

Order: environment events first (one incident explains many tests), then by failures, most first. The tab count is the number of groups and follows the search, like the Tests tab. Sort: Most failures, Most tests, Latest. Search (#/groups?q=) matches the template and the evidence text. Each card is one fingerprint: the message with numbers, ids, paths and times masked as ‹n›, ‹id›, ‹path› and ‹time›. A masked token is shown as a small grey tag so you can see what was replaced.

2. Cause chips and confidence

Likely cause: Timing and waits· High confidenceLikely cause: Order dependency· Medium confidenceLikely cause: Shared state or data· Low confidenceCause unknown
Timing and waitsOrder dependencyShared state or dataNetwork or external serviceEnvironment or resourcesConcurrencyLocator or UITime and randomnessInfrastructure
Design note

The chip is outlined, not filled, so it never looks like a status pill. The words carry the meaning: Likely cause, the cause name, then the confidence in words (High, Medium, Low). No colour codes confidence. The chip always says Likely, never states a cause as fact. Unknown has no confidence and no tip. Nine causes plus Unknown: Timing and waits, Order dependency, Shared state or data, Network or external service, Environment or resources, Concurrency, Locator or UI, Time and randomness, Infrastructure.

Design note

The tip sits inside the status note box, separated by a divider, so it reads as part of the same advice. It uses the wording 'probably' and names the cause with its confidence. The highlighted lines use the selection fill plus a dotted underline, so they do not depend on colour. 'See the group' links to that card on #/groups. Quoted log text is always shown as text, never as markup.

4. Cause tip copy (nine causes)

Cause, then the tip shown in the panel
Timing and waitsWait for something you can see on the page, not a fixed delay.
Order dependencyRun it alone to check, and let it set up its own state.
Shared state or dataGive each test its own data and clean up after it.
Network or external serviceMock the call, or retry only that call.
Environment or resourcesCheck the runner's memory, disk and CPU during the failing run.
ConcurrencyWait for the first to finish before you check.
Locator or UIUse a steady locator, such as a role or a test id.
Time and randomnessFix the time and seed the random values.
InfrastructureCheck the runner, then run it again.
Design note

Each tip has two short sentences: what probably happened, then one thing to do. Reading grade 8 or lower. Unknown adds nothing.
