## Method

- Positive class: tests whose ground-truth label is `flaky` (9 of the 22 lab tests; a test that runs in two Playwright projects counts once per project).
- History length N: the first N runs in `fixtures/lab/manifest.json` order (2 runs per commit). Only tests present in those runs count.
- Engine: the test gets the `flaky` label from `scoreTests` (a commit with both a pass and a fail).
- Baseline: Playwright marked the test flaky in any loaded run (`tests[*].status === "flaky"` in the raw JSON, that is, it failed and then passed on retry).
- Precision or F1 shows n/a when it is undefined (nothing predicted).

## Limits

This is a synthetic lab with 22 tests, one browser engine (Chromium, in a desktop and a mobile project) and 12 runs over 6 commits, with causes we injected ourselves with seeded outcomes and realistic error text (it validates the text rules, not real mechanisms). The test durations are simulated (seeded waits in the lab app, see `flake-lab/README.md`), so the wasted-time figures shown in the demo are realistic in size but are not measurements of a real suite. It shows the engine gives the known answers; it is not a real-world benchmark. The check against public real-world data (spec section 11.1, item 5) is a v1 item, because that dataset needs the JUnit importer.
