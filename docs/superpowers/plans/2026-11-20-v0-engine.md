# FlakeLens v0 Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the v0 analysis engine: project foundation, canonical data model, Playwright JSON importer, flake lab fixtures, and the flaky scoring and ranking engine, all as pure TypeScript with tests.

**Architecture:** `src/engine/` is pure TypeScript with no DOM and no UI imports (enforced by ESLint). Importers turn a vendor file into canonical records plus an import record. A `Dataset` collects imports. `scoreTests` and `rankTests` turn a dataset into ranked, labeled rows. The flake lab is a tiny static HTML app with deliberately flaky Playwright tests; running it produces the real fixtures and the sample data. The UI, worker, and IndexedDB storage come in the next plan.

**Tech Stack:** TypeScript (strict), Vite, React (shell only here), Vitest, fast-check, Zod, ESLint (typescript-eslint), Prettier, Playwright (flake lab only). Node v26.12.1, npm 12.0.2.

**Spec:** `docs/SPEC.md` (sections 6.1, 9, 9.1, 10, 11, 11.1, 13.2, 16, 17). Copy keys: `docs/ux/04-ux-copy.md`.

**Plan series:** this is plan 1 of the v0 build (build steps 1, 2, 2a and 3 in spec section 6.1). Plan 2, the v0 UI (step 4: worker, Dexie storage, screens from `docs/ux/wireframes/`, sample data, end-to-end and axe tests, GitHub Pages), is written after this plan lands.

## Global Constraints

- All files live under the project folder. npm cache and `PLAYWRIGHT_BROWSERS_PATH` already point to `.cache\` there; `.cache/` is git-ignored.
- `src/engine/**` must not import `react`, `react-dom`, anything under `src/ui/`, or any DOM API. ESLint fails the build if it does.
- No network calls anywhere in engine code or tests. The flake lab app is served from local files only.
- Every dependency costs $0 and has a permissive licence. Commit `package-lock.json`; CI installs with `npm ci`.
- TypeScript `strict: true`, plus `noUncheckedIndexedAccess: true`.
- Internal label values: `'flaky' | 'suspect' | 'failing' | 'stable' | 'insufficient'`. Display names (Flaky, Unproven, Failing, Stable, Not enough data) belong to the UI plan.
- The engine never produces user-facing text. Notices carry a `code` equal to the copy key in `docs/ux/04-ux-copy.md` (for example `import.partial.noStatus`) plus `params`.
- Thresholds live only in `src/engine/config.ts` (`DEFAULT_CONFIG`). Spec values: Failing at `>= 0.95` failure rate; Not enough data below 3 attempts or a single run with no retries; Unproven needs `m = 0`, at least 5 attempts and flip rate `>= 0.2`; an import fails when more than half its results are bad.
- Score: `S = 100 * (0.60 * W(m, g) + 0.25 * f + 0.15 * 4r(1-r))`, Wilson 95% lower bound with `W = 0` when `g = 0`.
- Label check order (first match wins): insufficient (skipped when `m >= 1`), failing, flaky, suspect, stable.
- Default sort: group order flaky, suspect, failing, stable, insufficient. Inside flaky: priority descending. Inside the other groups: score descending. Ties: file, then title.
- Imported strings are stored verbatim. The engine never strips, escapes, or interprets HTML.
- Git: initialise locally in Task 1. The remote is added when the user supplies the repo link. Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **UTF-8 BOM at the start of a report** (files saved by some Windows tools): the file must import, not fail as unreadable. Test in Task 4.
2. **Same file imported twice under different commit labels:** the run ID is content-based, so the second import must be flagged `import.dupeRun` and not double the history. Test in Task 5.
3. **A test whose every attempt is skipped:** no division by zero, label `insufficient`, never `stable`. Test in Task 7.
4. **Reports with no `stats.startTime`:** runs keep import order, run IDs stay unique, and nothing crashes. Test in Task 3.
5. **Same test in two Playwright projects (chromium and firefox):** two distinct `testId`s that share one `testKey`. Test in Task 3.

### Task 3: Playwright importer, valid input

**Files:**
- Create: `src/engine/import/schema.ts`, `src/engine/import/playwright.ts`, `fixtures/playwright/valid-basic.json`, `fixtures/playwright/two-projects.json`, `fixtures/playwright/no-start-time.json`
- Test: `src/engine/import/playwright.test.ts`

**Interfaces:**
- Consumes: types, `DEFAULT_CONFIG`, `hashString`.
- Produces: `parsePlaywrightReport(text: string, opts: { fileName: string; importedAt: string; commitLabel?: string; order: number; config?: EngineConfig }): ImportResult`. Never throws.

**Mapping rules (from spec section 9):**
- Walk `suites[*]` recursively (`suites[*].suites`, `specs[*].tests[*].results[*]`). The top suite is the file; `suitePath` is the chain of `describe` titles below it. `file` comes from `spec.file`.
- `testId = hashString([file, ...suitePath, title, project].join('\u0000'))`; `testKey` is the same without `project`. `project = test.projectName ?? ''`.
- `runId = hashString((stats.startTime ?? '') + '\u0000' + text)`. One run per file. `importId = hashString(opts.fileName + '\u0000' + opts.importedAt + '\u0000' + runId)`.
- `Run.commit = opts.commitLabel?.trim() || null`; when null, add notice `import.noCommit` (severity `info`, params `{ file }`). `Run.startedAt = stats.startTime ?? null`; `Run.order = opts.order`.
- Result status: `passed` → `pass`; `failed`, `timedOut` → `fail`; `skipped`, `interrupted` → `skip`.
- `attemptId = hashString(runId + testId + retry)`. `retryIndex = result.retry`. `durationMs = result.duration` when it is a finite number `>= 0`.
- One `Failure` per failed attempt: `message` and `stack` from `result.error ?? result.errors[0]`, empty strings when absent.
- Strip a leading `\uFEFF` before `JSON.parse`.

### Task 4: Importer, bad and partial input (spec section 9.1)

**Files:**
- Modify: `src/engine/import/playwright.ts`
- Create: `fixtures/playwright/{partial-no-status,partial-no-name,bad-duration,mostly-bad,wrong-format,truncated,empty,bom,deep-nesting}.json`
- Test: `src/engine/import/playwright.bad.test.ts`

**Rules:**
- Size: `text.length > config.maxFileChars` → `failed`, `import.fail.tooLarge`, params `{ file, limit: '50 MB' }`, before parsing.
- Unparseable JSON or empty text → `failed`, `import.fail.unreadable`.
- Parses, but no `suites` array or no `config` object → `failed`, `import.fail.format`.
- Suite depth above `config.maxSuiteDepth` → `failed`, `import.fail.tooLarge`.
- A result with no valid status → not imported; one `import.partial.noStatus` notice per test, params `{ count, test, run }`.
- A spec with a missing or empty title → all its results not imported; `import.partial.noName`, params `{ count, run, pos }` (pos = 1-based spec position in its suite).
- Duration not a finite number `>= 0` → kept with `durationMs: null`; one `import.partial.badDuration` notice with `{ count }`.
- Two tests with the same `testId` in one file → second gets `testId = hashString(oldId + '#' + index)`; notice `import.dupeIds`, `{ count }`.
- `notImported / found > config.maxBadShare` → `failed`, `import.fail.tooBad`, no records returned. Otherwise `partial` when `notImported > 0` or any warning notice exists, else `success`.
- Invariant: `imported + notImported === found`. `failed` imports return empty `runs`, `tests`, `attempts`, `failures`.

### Task 5: Dataset and de-duplication

**Files:**
- Create: `src/engine/dataset.ts`
- Test: `src/engine/dataset.test.ts`

**Interfaces:**
- Consumes: `ImportResult`, `Dataset`.
- Produces: `emptyDataset(): Dataset`; `addImport(ds: Dataset, res: ImportResult): Dataset` (pure, returns a new object). Runs whose `runId` already exists are dropped with their attempts and failures; the import record gets an `import.dupeRun` notice (severity `info`) and its `runIds` lose the dropped run. Tests are unioned by `testId`. Failed imports are kept in `imports` (the Loaded data screen lists them) but add no records.

- Produces: `countFlipsNaive(outcomes: boolean[]): number`; `countFlips(outcomes: boolean[]): number` (bit-packed); `wilsonLower(successes: number, trials: number, z: number): number` (returns 0 when `trials === 0`); `ema(values: number[], alpha: number): number` (returns 0 for an empty list; starts from the first value).

`countFlips` packs outcomes into 32-bit words (`true` = fail = bit 1) and, per word with `n` bits, adds `popcount((w ^ (w >>> 1)) & ((1 << (n - 1)) - 1))` (use `>>> 0` to stay unsigned; for `n = 32` the mask is `0x7fffffff`). It then adds one flip for each word boundary where the last bit of a word differs from the first bit of the next. JavaScript bitwise operators are 32-bit, which is why words are capped at 32 (spec section 10).

});
it('flip examples', () => {
  expect(countFlips([])).toBe(0);
  expect(countFlips([true, false, true])).toBe(2);
  expect(countFlips(Array(33).fill(false).map((_, i) => i === 32))).toBe(1);
});
it('wilson stays in [0,1] and grows with evidence', () => {
  fc.assert(fc.property(fc.nat(500), fc.nat(500), (a, b) => {

  }));

### Task 7: scoreTests and labels

**Files:**
- Create: `src/engine/score/score.ts`, `src/engine/score/testkit.ts` (test-only builder)
- Test: `src/engine/score/score.test.ts`

**Interfaces:**
- Consumes: `Dataset`, `EngineConfig`, Task 6 functions.
- Produces: `scoreTests(ds: Dataset, config?: EngineConfig): TestScore[]` (one entry per test, any order; `priority` filled in by Task 8, set 0 here).
- Produces (test helper, `testkit.ts`): `buildDataset(runs: Array<{ commit?: string; tests: Record<string, Array<'pass' | 'fail' | 'skip'>> }>, durationMs?: number | null): Dataset` — each run entry becomes one run in order; each array lists that test's attempts by retry index.

**Definitions (spec section 11), per test, skipped attempts excluded:**
- Attempts ordered by `run.startedAt` (nulls keep `run.order`), then `run.order`, then `retryIndex`.
- commit key = `run.commit ?? run.runId`. `m` = commits with both a pass and a fail. `g` = commits with at least two attempts.
- `f` = `countFlips(fails) / (n - 1)`, 0 when `n < 2`. `r` = `ema(fails as 0/1, emaAlpha)`.
- `score = 100 * (0.60 * wilsonLower(m, g, z) + 0.25 * f + 0.15 * 4 * r * (1 - r))`.
- `recentFailRate` = failure share over the last `failingWindow` attempts.
- `wastedMs` = sum of durations of failed attempts in mixed commits. `possibleWastedMs` = sum of durations of all failed attempts. `durationUnknown` = any counted attempt has `durationMs === null` (it counts as 0).
- `runs` = distinct runs with a non-skipped attempt; `retries` = attempts with `retryIndex > 0`.
- Label, first match wins: (1) `insufficient` if `m === 0` and (`n < minAttempts` or (`runs <= 1` and `retries === 0`)); (2) `failing` if `recentFailRate >= failingRate` (`wasFlakyEarlier = m >= 1`); (3) `flaky` if `m >= 1`; (4) `suspect` if `n >= suspectMinAttempts` and `f >= suspectMinFlipRate`; (5) `stable`.
- `isNew` = the test's first run is not the dataset's first run, and it has both a pass and a fail.
