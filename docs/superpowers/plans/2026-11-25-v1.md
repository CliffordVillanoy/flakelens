# FlakeLens v1 Plan

> **For the dev chat:** one DEV ticket at a time, as sent by the planning chat (tickets DEV-28 to DEV-46 in `docs/dev/`). Use superpowers:executing-plans and superpowers:test-driven-development per ticket. Branches, pull requests, merges, tags, version numbers and every CI/CD change belong to the **Project Dev Ops chat**, not to this plan or the dev chat.

**Goal:** Turn the shipped v0 (ranked flaky tests from Playwright JSON, live on GitHub Pages) into v1: more input formats and richer run data, failure grouping with likely causes, investigation screens, exports, settings, and an installable offline app, with the flaky detector checked on real-world data.

**Architecture:** Same as v0. The engine in `src/engine/**` stays pure TypeScript (no DOM, no UI, no network). Importers turn a vendor format into the canonical records; the analysis modules (fingerprints, causes, correlations) read the dataset and return plain data; the UI in `src/ui/**` renders it. Everything runs in the browser; nothing leaves it. Parsing stays in the Web Worker.

**Tech stack additions (all $0, permissive licences, versions reported per ticket):** an XML parser for JUnit (chosen in DEV-32, must have DTD and external entities off), `vite-plugin-pwa` (DEV-42). Everything else is already installed.

**Spec:** `docs/SPEC.md` sections 6 (v1 row), 9, 9.1, 10, 11.1, 12 (category list only), 13, 13.3, 15, 16, 19.1. Design: `DESIGN.md`, `docs/ux/`. Security: `docs/security/review-2026-11-22.md` and the acceptance lines in `docs/dev/README.md`.

## Global constraints (every ticket)

- No network calls by default; no new accounts, secrets or tracking while the app stays on GitHub Pages.
- `src/engine/**` keeps its lint rules. New engine code is pure and has unit tests; every regex or loop over untrusted text has a bounded quantifier or a linear algorithm **and a timing test** (hostile 1 MB string finishes in under 500 ms).
- Imported text renders as text only; exports use the shared helpers in `src/ui/lib/safeText.ts`.
- All visible text comes from `src/ui/copy.ts`. New copy keys are interim until the UI/UX chat confirms them (list them in the report).
- UI text follows the word budgets and rules in `docs/ux/12-simplification-pass.md` (Start 40, Tests 60, Loaded data 60, detail panel 90, dialog 45, banner or toast 20 visible words above the first data row): say it once, tooltips hold explanations, rare choices live in Settings, one primary button per screen. Rule 8: no grey helper line under a label; a helper stays only if it prevents a mistake.
- Stored data changes keep `schemaVersion` rules from DEV-20: new fields are optional, a v0 stored row must still load (test it).
- Thresholds live in `src/engine/config.ts` with tests.
- A new dependency needs: licence, version, reason, and a check that it is not in the main bundle unless meant to be. Report each one.
- Plain commit messages, no Claude attribution.

## Review Focus (for the final v1 review, DEV-43)

1. **A JUnit file that is XML-bomb, XXE, 50 MB, or 10,000 levels deep:** fails with a notice inside the worker, the page never freezes.
2. **A failure message of 5 MB:** fingerprinting, grouping, classifying and the log viewer stay responsive and bounded.
3. **Run metadata missing or hostile** (a shard of `-1`, a browser named `<script>`, a 10,000-character branch): stored, shown as plain truncated text, never trusted for logic without validation.
4. **A report with the same test in 3 browsers and 4 shards:** correlation output stays correct and small-sample results are not presented as findings.
5. **Offline and update:** after install, the app works with the network off; after a new deploy, an old tab updates without serving mixed old and new files.

## Risks to watch

- **Playwright JSON field names** for git info, shard and browser are not verified against a real 1.65 report in this plan. DEV-30 starts by producing real reports from the flake lab with git capture on and records the exact field paths found.
- **Public datasets** may be unusable (licence, format, size). DEV-33 starts with a go or no-go step and reports Blocked rather than guessing.
- **Cause classifier honesty:** rules will be wrong sometimes. Every cause is "likely", carries quoted evidence, and DEV-36 publishes a confusion matrix on the lab, with its limits.
- **Scope creep toward v1.5** (LLM explanations) and v2 (false-pass and false-fail detectors): not in this plan.
